# UI automation with FlaUI - the mechanics

`SKILL.md` keeps the logic in presenters and ViewModels, which unit-test with a mocked view; end-to-end UI tests stay at smoke and the critical path. This file is how those few are built so they stay green for the right reason. Test framework, runner and assertions are the `dotnet-testing` skill's.

- **Backend: UIA2** (`FlaUI.UIA2`, `new UIA2Automation()`). FlaUI's own notes: UIA3 can misbehave on WinForms - its Slider reports a fixed 0-100 range under UIA3 - while UIA2 does not support its Spinner. Pick UIA2, and switch one test to UIA3 only for a control UIA2 cannot drive.
- **Locators, in this order: AutomationId -> Name -> class name.** `cf.ByAutomationId(...)` survives a relabel and a translation; `cf.ByName("Save")` breaks on the first translation; `cf.ByClassName(...)` only separates siblings nothing else tells apart. Give every control a test touches a stable design-time `Name`, and confirm in FlaUInspect which AutomationId it actually exposes before writing the locator. An AutomationId is unique only among SIBLINGS, so search from the form or a container, never from the desktop root.
- **One page object per form.** A class wrapping that window's element, its controls as properties found on access, its user actions as methods (`SaveAs(name)`) - the test reads as the user's steps, and a changed locator is fixed in one place. Assertions stay in the test.
- **Explicit waits, never a sleep.** Find through `Retry.WhileNull(() => window.FindFirstDescendant(cf => cf.ByAutomationId("resultLabel")), timeout: TimeSpan.FromSeconds(5), throwOnTimeout: true)`, and wait out a closing dialog with `Retry.WhileTrue(() => dialog.IsAvailable, ...)`. A `Thread.Sleep` is too short on a loaded CI box and wasted time everywhere else.
- **Launch and teardown per test class.** `Application.Launch(exePath)`, then `app.WaitWhileMainHandleIsMissing()`; dispose the automation object, and end the process in teardown (`app.Kill()` when a graceful close fails) so a hung instance never leaks into the next test.
- **CI: a `runs-on: windows-latest` job** runs the smoke suite on every pull request, after the unit suite. UI Automation needs a live desktop session - a self-hosted runner installed as a Windows service has none, so start it with `run.cmd` in a logged-on session instead. A test that passes locally and fails in CI on an element not found checks the session before the locator.
